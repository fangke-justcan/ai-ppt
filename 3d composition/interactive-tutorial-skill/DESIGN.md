# 交互（游戏化）教程制作方法论 — 从紫金花课堂到通用 Skill

本目录是一次完整实践：把 `subpixel-bijection-flow` 项目里的知识做成 10 关交互教程。
本文档沉淀制作过程中的经验，作为未来泛化成通用 skill（让任何学生用自己的项目
做交互教程）的设计底稿。

## 〇、硬标准（用户反馈两轮后确立，做新教程时先对照）

1. **交互先行，进关零讲解**：进入关卡直接看到可玩的 demo + 顶部挑战条，
   没有任何前置文字。挑战条件写进挑战条（text + hint），必须**可自动判定**。
2. **挑战成功后的讲解动画**：win() 触发印章庆祝后，讲解卡片才逐张播出——
   每张锚定在它解释的交互元素旁（`near` 选择器 + 自动定位，临近原则），
   文案是**解释刚才发生的事**（过去时），不是操作指引；支持「继续」手动推进
   和 `after` 毫秒自动推进；播完收成右栏编号 pin，可点回看，也可点「重播讲解 ▸」
   重看整段动画。已通关的关卡再进入时直接收为 pin，不自动播放。
3. **单屏完成**：每关一页装下（头部 + 挑战条 + demo 区 + 右栏 + 页脚小结），
   不翻页、不长滚动。空间设计：左 demo 右栏（讲解回放 / 问题 / 通关详解）。
4. **去 AI 味清单**（视觉）：暖纸底色 + 墨色文字 + 单一朱红强调色；
   标题用衬线字体制造"编辑部落感"；禁用：紫蓝渐变、发光、阴影卡片堆、
   emoji 图标、圆角大卡片阵列、营销话术。庆祝动效用「完成」印章 + 稀疏墨点，
   不要满屏彩纸。
5. **核心版 5~7 关，讲透 > 覆盖**：挑 3~5 个关键魔法时刻做成核心关
   （本示例：并行 → 双射 → 反馈 → ping-pong → 演化 → 毕业）；
   被砍掉的知识点做成独立插件放进 lessons-ext/ 扩展池，
   想学的用户把 <script> 插到想要的位置即可继续加关。
   跨关引用一律用关卡名，不写编号（关卡会增删重排）。

## 一、课程设计公式（核心）

每一关 = **玩 → 挑战 → 讲解动画 → 通关详解** 四段式：

| 段落 | 作用 | 设计要求 |
|------|------|----------|
| 🎮 demo build | 进关即玩 | 画布 + 控件 + 实时读数，所有操作即时可见反馈；无任何前置讲解 |
| ⚔️ 挑战 goal | 游戏化目标 | 挑战条置顶展示；条件**可自动判定**（程序检测 → 自动 win） |
| 📝 讲解动画 notes | 通关后播出 | 每张 ≤3 行、带标题、锚定相关元素旁；文案为**过去时解释**（"你刚才…是因为…"）；逐张播出、收成 pin 可回看、可重播 |
| 📖 通关详解 theory | 右栏文字版 | 生活比喻 + 项目真实代码摘录（注明文件名） |
| 📌 小结 takeaway | 一句话 | 页脚展示，通关后可见 |

## 二、知识点拆解方法

从项目中找知识点时按这个顺序：

1. **列出项目的 3~5 个"魔法时刻"**（画面为什么会动？为什么不糊？为什么最终变均匀？）
2. **每个魔法时刻倒推一个最小可玩模型**——用 Canvas 2D / 几十行 JS 复刻其本质，
   而不是复刻项目全部。例如：D() 六层波 → 五层按钮叠加实验；ping-pong → 两个水桶单步动画。
3. **排序遵循依赖链**：像素是什么 → 坐标是什么 → 波是什么 → 叠波 → 搬运规则 →
   反馈 → 双缓冲 → 总演化 → 毕业。每关只依赖之前关卡的概念。
4. **课程数量 8~12 关**。每关 3~10 分钟。

## 三、引擎契约 v2（复用此结构做新教程时只换 lessons/）

```
tutorial/
├── index.html      # 外壳：目录侧栏 + 主区 + #err 错误显示
├── style.css       # 纸面编辑风主题（见第〇节去 AI 味清单）
├── engine.js       # 通用引擎，与具体内容无关：
│                   #   LESSONS 注册 / 解锁 / localStorage 进度 /
│                   #   goalbar 挑战条 + win() 印章庆祝 /
│                   #   notes 时序注释卡片（near 锚定 + after 自动推进 + 收成 pin）/
│                   #   rail 右栏（边玩边讲 pins / 问题 quiz / 通关讲解）/
│                   #   toast / 音效 / TU 工具箱
├── lessons/*.js    # 纯内容插件：
│                   # { id, title, sub, goal:{text,hint}, build(demoArea,api),
│                   #   notes:[{near,title,html,after,pos}], theory:{story,code},
│                   #   takeaway }
├── server.js       # 静态服务器（Cache-Control: no-cache + '/' 301 重定向）
└── DESIGN.md       # 本文件
```

课程插件可用的 API：`api.TU`（canvas/slider/button/readout/quiz/hash21/flower…）、
`api.row()` 双列布局、`api.win(msg)`、`api.onCleanup(fn)`（**一切 interval/rAF 必须注册**，
否则切关泄漏）、`api.quiz(questions, onAllCorrect)`（挂到右栏问题区）、`api.toast`。

经验教训：`TU.readout` 返回的必须是增强后的 DOM 元素（`ro.set(html)` 与
`ro.innerHTML` 两种写法都要能用）——课程代码两种写法混用时，包装对象会静默吞掉更新。

## 四、实测踩过的坑（做新教程时对照检查）

1. **服务器 `/` 不能"代填内容"**：必须 301 重定向到子目录，否则页面内相对路径
   （style.css、engine.js）全部 404，且资源 404 是静默的（不触发 window.onerror，
   需要捕获阶段监听才能抓到）。
2. **浏览器缓存旧 JS**：教学内容会反复迭代，静态服务器必须发
   `Cache-Control: no-cache`，否则改了课程浏览器还在跑旧版（本次实测踩中）。
3. **TDZ**：demo 的"后台预计算"等异步循环若引用了后声明的 const 组件，会把
   build 炸掉。所有 readout/控件先创建，再启动循环。
4. **定时器泄漏**：切关不清 interval 会越积越多。统一走 api.onCleanup。
5. **整数位移让反例失效**：教学用的"反例"（不取整→磨糊）必须保证参数真的产生
   效果（小数位移才发生混合；整数插值=原样复制）。做反例时要先自动把参数拨到
   能产生现象的位置。
6. **验证方式**：node --check 全部 JS → 浏览器 #err 为空 → evaluate 驱动全流程
   自动通关（可 localStorage.clear() 后重放）→ 每关截图看视觉。注意 IAB 截图
   偶发"Internal error"/半帧毛刺，重试即可（工作区已知问题）。

## 五、泛化为通用 Skill 的路线（待做）

把上面抽象成 SKILL.md，输入=任意项目，输出=一个 tutorial/ 目录：

1. **调研阶段**：读项目 README + 核心源码，让 LLM 列出"魔法时刻"清单，用户勾选。
2. **拆解阶段**：按第二节方法产出关卡大纲（每关：知识点/比喻/交互模型/挑战判定条件/
   注释卡片序列）。
3. **生成阶段**：复用 engine.js/style.css/server.js 原样拷贝，只生成 lessons/*.js
   （skill 里内置 demo 模板：网格像素类、坐标hover类、参数滑块类、逐帧动画类、
   双状态机类、quiz 类——本次 10 关全部落在这些模板上）。
4. **主题适配**：style.css 遵守"去 AI 味清单"换强调色与字体（本项目→纸墨+朱红）。
5. **验收阶段**：按第四节清单自动检查 + evaluate 全流程通关测试 + 每关截图
   （对照三条硬标准：交互先行？注释卡片锚定临近？单屏装下？）。

> 一句话：**交互先行、讲解以时序注释卡片贴着交互元素出现、单屏装下、视觉去 AI 味；
> 引擎与内容插件分离，demo 归约为六种模板，挑战必须可自动判定。** 满足这些，
> 任何项目都能套。
