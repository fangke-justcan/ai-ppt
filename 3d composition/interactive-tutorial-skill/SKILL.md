# SKILL · 把任意项目做成游戏化交互教程

> 输入：**任何**一个你自己的项目（shader / 算法 / 网页 / 工具 / 硬件……）。
> 输出：一个 `tutorial/` 目录——纯静态、零依赖、**核心 5~7 关**、可直接挂 GitHub Pages
> 的游戏化交互课堂；先讲透关键知识点，其余进扩展池，想学随时继续加关。

本仓库的 `lessons/` + `engine.js` 就是这套 skill 的完整示例
（示例项目：Shadertoy [Subpixel Bijection Flow](https://www.shadertoy.com/view/73c3R7) 的紫金花改造版）。

---

## 〇、四条硬标准（产出前先对照，验收时逐条检查）

1. **交互先行，进关零讲解**：进入关卡直接看到可玩的 demo + 顶部挑战条，没有任何前置文字。
   玩法线索全部写进挑战条的 `text` + `hint`。
2. **挑战成功后才出讲解，且是动画形式**：达成挑战 → 庆祝动效 → 讲解卡片逐张播出。
   每张卡片**锚定在它解释的交互元素旁边**（临近原则），文案用过去时解释
   "你刚才……是因为……"，而不是操作指引。播完收成侧栏 pin 可回看、可重播。
3. **单屏完成**：每关一页装下（头部 + 挑战条 + demo 区 + 右栏 + 页脚小结），
   不翻页、不长滚动。
4. **去 AI 味视觉**：暖纸底色 + 墨色文字 + **单一**强调色；标题衬线字体；
   禁用紫蓝渐变、发光、emoji 图标、圆角大卡片阵列、营销话术；
   庆祝动效克制（印章 + 少量碎点，不要满屏彩纸）。

## 一、四阶段工作流

### 阶段 1 · 调研：找"魔法时刻"

读项目的 README 和核心源码，问自己：**这个项目里什么是反直觉的？**
列出 3~6 个"魔法时刻"。示例（紫金花项目）：

| 魔法时刻 | 倒推出的知识点 |
|---|---|
| 图案在所有分辨率下都一样 | UV 坐标 |
| 画面动起来但内容永不衰减 | round+mod 双射搬运 |
| 不画新东西画面却在演化 | 自反馈（读上一帧） |
| 读自己却不冲突 | ping-pong 双缓冲 |

### 阶段 2 · 拆解：关卡大纲

- **核心版只做 5~7 关**。知识点不求全覆盖——挑 3~5 个**关键魔法时刻讲透**，
  比面面俱到重要十倍；其余知识点进「扩展池」，核心版发布后想学的用户自然会催你继续加。
- **按依赖链排序**：每关只依赖之前关卡的概念（示例：像素 → 双射 → 反馈 → ping-pong → 总演化 → 毕业）。
- 第 1 关当"预告片"，最后一关当"毕业测验 + 自由实验室"。
- 每关写四样东西：知识点 / 生活比喻 / 最小可玩模型 / 挑战的自动判定条件。
- **扩展池**：被砍掉的知识点做成独立插件文件放进 `lessons-ext/`（含一行加法说明），
  谁想学，把 `<script>` 插到想要的位置即可，核心代码一行不用改。

跨关引用一律用**关卡名**，禁止写编号——关卡会增删重排，名字不会变。

### 阶段 3 · 生成：拷骨架，写插件

拷贝本仓库的 `index.html` `style.css` `engine.js` `server.js` `start.bat`，
**删掉 `lessons/` 里的示例**，然后每关写一个插件文件：

> 本仓库的 `lessons/`（核心七关）+ `lessons-ext/`（扩展池，暂未挂载）
> 就是这个结构的活示例：先上核心，`lessons-ext/README.md` 演示了"继续加关"怎么加。

```js
LESSONS.push({
  id: 'my-lesson-3',
  title: '关卡的名字',            // 不要 emoji
  sub: '一句话副标题',
  goal: { text: '挑战做什么', hint: '卡住了看这里' },
  build(demoArea, api) { /* 挂 demo；达成时调 api.win() */ },
  notes: [                         // 通关后逐张播出的讲解动画
    { near: '.fig', title: '你刚才做了什么',
      html: '过去时解释：你刚才……是因为……', after: 9000 },
  ],
  theory: { story: '完整讲解（含比喻）', code: { src: '你项目里的文件名', html: '真实代码' } },
  takeaway: '一句话小结',
});
```

可用工具（`api.TU`）：`canvas / slider / button / readout / quiz` 等；
`api.row()` 双列布局；`api.onCleanup(fn)` 注册清理（**一切 interval/rAF 必须注册**）；
`api.win(msg)` 达成挑战；`api.quiz(questions, onAllCorrect)` 把测验挂进右栏。

**demo 归约为六种模板**（本次 10 关全部落在其中）：

| 模板 | 适合的知识 | 示例关 |
|---|---|---|
| 网格像素 | 并行、规则计算 | 第 2 关 |
| 坐标悬停 | 坐标系、参数含义 | 第 3 关 |
| 参数滑块 | 公式与参数的对应 | 第 4 关 |
| 逐帧动画 | 运动、演化过程 | 第 5/7/9 关 |
| 双状态机 | 资源交替、协议 | 第 8 关 |
| 测验 | 概念收束 | 右栏组件 |

写 demo 的原则：**把项目算法砍到能用几十行 Canvas 2D 复刻本质为止**，
并让每个操作都有实时数字读数——把不可见的数学变成可见的数。

### 阶段 4 · 验收

```bash
node --check engine.js lessons/*.js   # 语法
node server.js 8945                   # 打开页面：#err 必须为空
```

然后浏览器里逐关自动通关（或手玩），并逐条对照：

- [ ] 进关时一张讲解卡片都没有？
- [ ] 挑战是否可自动判定、通关后讲解动画是否逐张播出？
- [ ] 每关是否单屏装下（1366×768 不出滚动条）？
- [ ] 核心版是否 ≤7 关？砍掉的知识点是否进了扩展池？
- [ ] 跨关引用是否全部用关卡名（没有编号）？
- [ ] 视觉是否过了"去 AI 味清单"？
- [ ] 每个操作的反馈是否即时可见（读数变了没）？

## 二、已知坑（都真踩过）

1. 静态服务器对 `/` 必须 **301 重定向**到真正的 index，不能"代填内容"，
   否则页面内相对路径（css/js）全部 404；而资源 404 是静默的，要用捕获阶段
   `addEventListener('error', fn, true)` 才抓得到。
2. 服务器必须发 **`Cache-Control: no-cache`**：教程内容会反复迭代，
   浏览器缓存旧 JS 会让你"改了没生效"排查半天。
3. demo 里的后台循环若引用了后声明的组件（TDZ）会炸掉整个关卡——
   控件先创建、循环后启动。
4. `readout` 工具返回的必须是增强后的 DOM 元素，兼容 `set()` 和 `innerHTML`
   两种写法，否则课程代码混用时会静默吞掉更新。
5. 教学用的"反例"参数必须真的产生现象（例：整数位移下线性插值等于原样复制，
   看不出磨糊）——做反例前先把参数拨到会产生可见后果的位置。
6. 切换关卡时旧定时器必须清理（`api.onCleanup`），否则越切越卡。
