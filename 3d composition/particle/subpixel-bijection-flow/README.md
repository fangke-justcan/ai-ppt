# Subpixel Bijection Flow · 紫金花版 — 本地副本

Shadertoy 原作 [Subpixel Bijection Flow](https://www.shadertoy.com/view/73c3R7)
（chronos, 2026-09）的本地 WebGL2 运行器 + 「紫金花」改造版，带实时参数面板。

**紫金花改造**：画布中心一朵五瓣紫金花（花瓣朝上），花内是离散的紫/金
**粒子群**（哈希撒点 + 金色花蕊），粒子被剪切流搬运、在花形域内碰撞混合；
粒子云周期性向外膨胀压向花瓣壁，压壁处亮起鎏金后回弹；花外像素静止。
花朵大小约为画面短边的 16%，可在面板调节。

## 运行

```bash
node server.js 8944        # 或双击 start.bat
# 浏览器打开 http://localhost:8944/
```

验证方式与工作区惯例一致：打开页面后确认 `#err` 元素为空（shader 编译错误会写进去）。
端口用 8944，与 fractured-orb 的 8942 互不冲突，可同时运行。

## 交互教程（tutorial/）

`tutorial/` 目录是一个面向小白的**游戏化交互课堂**（10 关）：像素并行、UV 坐标、
sin 条纹、多频叠加、round+mod 双射、自反馈、ping-pong、帧数驱动演化，最后一关
毕业测验发「紫金花搬运士」徽章。全部原生 JS Canvas，无依赖。

```bash
node tutorial/server.js 8945   # 或双击 tutorial/start.bat
# 浏览器打开 http://localhost:8945/  （同服务器下 /index.html 是本尊主程序）
```

进度存 localStorage，侧边栏有「教师模式」可一键解锁全部关卡。课程结构（引擎与
课程插件分离、四段式关卡公式、踩坑清单）见 `tutorial/DESIGN.md` —— 那也是未来
把它泛化成"任意项目做交互教程"的 skill 的设计底稿。

## 通道结构（原作 + 花域改造）

- **Buffer A**：自反馈模拟 —— iChannel0 绑定**本通道上一帧输出**（Shadertoy 内部
  ping-pong）。每帧对图像做逐通道的行/列错位搬运：错位量 = 黄金角漂移 + 多频余弦
  域扭曲，`round()` 取整保证像素双射（不丢不重），三通道错位相位各差 0.05。
  前 9 帧写入紫金花种子图案。
- **花域约束（改造点）**：花瓣包络 `R(θ) = R0·(floor + (1-floor)·|cos(nθ/2)|^sharp)`
  定义花形。演化帧把错位后的采样点转到极坐标，用 **w=(r/R)² 的 fract 回卷**
  （面积坐标环面双射）把出界粒子送回花心重新进入 —— 内容不衰减。
  教训：不要用"沿极径折叠"、径向呼吸或输运层 θ 向环流——位移场 + 固定壁
  会形成单向棘轮/月牙丢失/离散折叠，内容几十帧内衰减消失（全部实测）。
- **粒子化种子（改造点）**：花内不是连续渐变，而是确定性哈希撒点的离散
  粒子群（3px 网格；紫为主、金粒子沿瓣中脉偏置 + 实心金色花蕊）。输运
  映射只搬运不磨平，"粒子感"永久保持。密度由面板"粒子密度"调节。
- **边界物理感知（全部在 Image 显示层，零风险）**：
  - **呼吸压壁**：粒子云按正弦相位整体向外膨胀，外圈粒子被花瓣壁截住
    压进边界随后回弹 —— 一压一弹周期可见；
  - **压壁金光**：金光 ∝ 外圈带 × 压壁相位²，压得最狠时花缘亮起鎏金；
  - **常驻鎏金描边**：细环带保持底光标出容器轮廓；
  - **花外像素严格直通**：呼吸/旋转/金光绝不泄漏出花域
    （曾因缺域内掩码导致花外全橙——已修）。
- **整体旋转**：一朵花作为整体缓缓转动（同一角度）。早期用差异化旋转
  （外圈快内圈慢），内容被撕成多层环、看起来像两朵花在转——已改。
- **Image**：合成显示 = 整体旋转 + 呼吸采样后的内容 + 压壁金光。
  Buffer A 的 RGB 只存纯内容，显示层特效不污染模拟。

无外部纹理输入。采样器契约（linear+clamp+vflip）因只使用 `texelFetch` 而不参与
实际采样，但已在运行器中按原作配置。

## 与 fractured-orb 运行器的差异

fractured-orb 的 Buffer A 不自反馈（每帧独立渲染）；本项目 Buffer A **读自己上一帧**，
运行器改为标准 ping-pong：读 `bufTex[bufRead]` 写 `bufFbo[1-bufRead]`，帧末交换。
窗口缩放重分配缓冲后把 `iFrame` 归零，让种子图案重新播种（否则反馈内容丢失会黑屏）。

## 已知行为（非 bug）

- **画面演化节奏由帧数驱动**：shader 时间 = `iFrame/60`。浏览器后台节流（rAF 暂停）
  时演化变慢但不失真；Shadertoy 网页在编辑器聚焦时同样节流，所以"墙钟 8 秒"对应的
  帧数可能远少于 8×60。
- **演化轨迹**（`analysis/` 下截图 + `cpu_sim.js` float64 参考模拟证实）：
  种子花(0~9 帧) → 花内剪切卷流(几十帧起金色卷入) → 花内均匀颗粒混色(数百帧后)。
  混色趋于均匀是这类输运映射的固有性质（原作全屏版最终也变成均匀噪点），
  按 `R` 可重新播种观看全过程；轮廓、大小、亮度长期稳定（f508 实测均值 33.8 vs
  种子 30.6）。
- **GPU 浮点差异**：错位量在整数边界附近对 float32/64 舍入敏感，不同 GPU/分辨率下
  细节颗粒分布会略有出入，宏观结构一致。

## 文件

- `shaders/bufferA.frag` — 参数化 + 紫金花改造版（原作硬编码常量 → `u*` uniform）
- `shaders/bufferA.orig.frag` / `image.orig.frag` — 原作未修改备份（字节级一致）
- `source/shader.json` — 页面 `/shadertoy` 端点返回的完整原始数据存档
- `tutorial/` — 面向小白的 10 关游戏化交互课堂（见上节，方法论在 `tutorial/DESIGN.md`）
- `analysis/cpu_sim.js` — CPU 参考模拟（`node cpu_sim.js [W] [H] [frames]`），
  用于仲裁 WebGL 运行器输出的正确性；教程第 9 关的"时间机器"就是它在浏览器里的移植
- `analysis/flower_seed_f8.jpg`、`particles_press_f40.jpg` / `particles_relax_f120.jpg`
  — 粒子版验证截图（种子 / 压壁峰值 / 松弛回弹）
